## Description
The binary save format (RGF v1.21) uses hand-written `LoadFromStream`/`SaveToStream` on every `GameEntity` subclass. Asymmetries between read and write are the most common source of bugs in roguelikes. Audit every serialization path.

## Files to Review

### Core save/load orchestration
- **NWGameSpace.cs** (~lines 1600-2700) — `SaveGame`, `LoadGame`, `SaveTerrain`, `LoadTerrain`, `SavePlayer`, `LoadPlayer`
- Verify: file sections are written/read in the same order, version branching is consistent

### Entity serialization
- **Player.cs** — save/load methods (extends NWCreature, adds satiety, faith, craft, memory)
- **NWCreature.cs** — save/load (abilities, items, effects, AI state, stats, equipment slots)
- **Item.cs** — save/load (including container contents — `ItemStreamTests.ContainerRoundTrip` covers basic case but not nesting >1, null containers, zero-count)
- **Effect.cs** / **EffectsList.cs** — known issue: "ProwlingEnd, EffectsList" exceptions on exit
- **NWBrainEntity.cs** — save/load (dynamic goal dispatch via `SerializablesManager.CreateSerializable`)
- **NWGoalEntity.cs** and all subclasses — each goal saves its own state
- **Journal.cs** / **JournalItem.cs** — save/load
- **Ghost.cs** / **GhostsList.cs** — save/load
- **Score.cs** / **ScoresList.cs** — save/load
- **Memory.cs** / **MemoryEntry.cs** — save/load
- **Debt.cs** — save/load
- **NWGameSpace.cs** quest references

### File format helpers
- **FileHeader.cs** — sign/version header read/write
- **Archive.cs** — file I/O wrapper

## Method
For each file:
1. Print the `SaveToStream` lines
2. Print the `LoadFromStream` lines
3. Compare line-by-line for field order, field count, and type matches
4. Check version branching — does `Load` handle old formats? Does `Save` always write the latest?

## Acceptance Criteria
- [ ] Every save/load method pair is reviewed
- [ ] All asymmetries are documented
- [ ] Confirmed-correct pairs are marked as such
- [ ] Bug issues are created for each confirmed asymmetry
- [ ] The review notes are committed to a `dev_info/audit/` summary file

## Notes
- Debug build has `CheckForOverflowUnderflow=true` — not relevant here but good to know
- `NWBrainEntity.SaveToStream` skips goals with `SerializeKind <= 0` — verify this is intentional
- Look for `BinaryReader`/`BinaryWriter` calls where read doesn't match write (different field count, different type)
- The `FileVersion` parameter is critical — check branching logic
- `ISerializable` pattern is used throughout — verify `SerializeKind` is consistent
