## Description
The goal-oriented AI system controls NPC behavior via brain types and goal subclasses. Review the dispatch mechanism and verify each brain type handles its tick without throwing.

## Scope

### Brain dispatch
- `NWBrainEntity` — base class, serialization, goal management
- `BeastBrain` — basic animal AI (wander + attack nearby)
- `SentientBrain` — civilized NPC AI (services: teach, trade, exchange, recruit)
- `WarriorBrain` — aggressive combat AI
- `TraderBrain` — merchant AI
- `VictimBrain` — fleeing AI
- `LeaderBrain` — pack leader AI
- `RavenBrain` — Odin's raven (special)
- `EitriBrain` — dwarven smith (special)
- Brain type → CreatureEntry mapping (how does the DB determine which brain a creature uses?)

### Goal system
- `NWGoalEntity` — base class
- Goals: `AreaGoal`, `AreaGuardGoal`, `DebtTakeGoal`, `EnemyChaseGoal`, `EnemyEvadeGoal`, `EscortGoal`, `FlockGoal`, `ItemAcquireGoal`, `LocatedGoal`, `PlayerFindGoal`, `PointGuardGoal`, `ShopReturnGoal`, `StalkGoal`, `TravelGoal`, `WareReturnGoal`
- Goal priority/conflict resolution — when multiple goals are active, which takes precedence?
- Goal serialization (cross-ref Issue 1.1)

## Method
1. Document brain type dispatch (how `CreatureEntry` → brain class)
2. Verify each brain type's `Process()` method handles the tick without throwing
3. Review goal priority: if a creature has EnemyChaseGoal and TravelGoal, which wins?
4. Cross-reference DOS manual creature behaviors:
   - "Blur: fastest creature" → check Speed value
   - "Cockatrice: can petrify with its gaze" → check EffectID associations
   - "Werewolf: bite can induce lycanthropy" → check effects
   - "Fyleisch: surrounded by lethal mist" → check FyleischCloud

## Acceptance Criteria
- [ ] Brain dispatch mapping documented
- [ ] Each brain type verified to tick without exceptions
- [ ] Goal priority/conflict rules documented
- [ ] Cross-reference of manual creature behaviors to code
- [ ] Bug issues filed for behavioral discrepancies
