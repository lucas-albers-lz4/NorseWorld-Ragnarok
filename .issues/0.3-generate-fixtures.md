## Description
Regenerate the committed test fixtures from a fresh headless game. The existing golden saves in `dev_info/fixtures/save/` may be stale if the save format version changed (NWGameSpace.RGF_Version).

## Fixtures to Regenerate
1. **slot8/** — village in-world save created by `build-fixture`
2. **container/** — slot8 + Flask with Torch inside (created by `build-container-fixture`)
3. **effects/** — slot8 + prowling effect on player (created by `build-effects-fixture`)

## Implementation
```bash
mono NWR.Harness build-fixture
mono NWR.Harness build-container-fixture
mono NWR.Harness build-effects-fixture
```

## Acceptance Criteria
- [ ] All three fixture scenarios log "OK"
- [ ] None produce log failure patterns
- [ ] Fixtures are committed to git (they're small — a few KB each)
- [ ] After regeneration, `save-load-roundtrip`, `container-roundtrip`, and `effect-persist` scenarios pass (re-run Issue 0.2)

## Notes
- Fixture generation uses non-deterministic world gen — each run produces a different world
- The golden saves lock in whatever world was generated — they're for regression, not reproducibility
- If RGF version changed, ALL fixtures MUST be regenerated
- The `NWResourceManager.GetAppPath()` must resolve to repo root (where `resources/` and `languages/` live)
- The HarnessBootstrap sets `Debug_DevMode = false`, so inventory limits apply realistically

## Danger
- Do NOT commit `save/rgame_*.*` files — they're gitignored
- Only commit fixture files under `dev_info/fixtures/save/`
