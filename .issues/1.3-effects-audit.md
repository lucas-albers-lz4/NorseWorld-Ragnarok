## Description
The effects system has 230+ magic effects covering instant cast, persistent buffs/debuffs, rays, clouds, and timed expiration. Known issues (quit-time exceptions on `ProwlingEnd`, `EffectsList`) suggest latent bugs.

## Scope

### Effect lifecycle
- `Effect.Execute()` — maps `EffectAction` to behavior
- Effect tick processing in `ProcessGameStep()`
- Duration decrement and expiration
- Cleanup on removal

### Effect types
- **Instant** (`ea_Instant`) — fire-and-forget
- **Persistent** (`ea_Persistent`) — stays on target, ticks each turn
- **Mixed** — instant + persistent component
- **Rays** — projectile effects (`FireRay`, `IceRay`, `PolymorphRay`, `DeathRay`, `StoningRay`, etc.)
- **Clouds** — `FyleischCloud` area-effect

### Key areas
- `Effect.Assign()` — cumulative/stacking logic
- `EffectsList` — add/remove/tick/clear
- `EffectsFactory` — effect creation from data
- `EffectRec` / `EffectProcRec` — database-backed effect definitions
- `EffectTarget` — who/what the effect targets
- `InvokeMode` — how the effect is delivered (self, target, beam)

### Per-ray subclass review
Each ray in `Effects/Rays/` has its own hit logic and side effects:
- `AnnihilationRay` — instant kill
- `BlackGemRay` — HP drain to caster
- `CancellationRay` — dispel magic
- `DeanimationRay` — undead destroy
- `DeathRay` — death or big damage
- `FireRay` — fire damage
- `FireVisionRay` — gaze attack
- `FlayingRay` — armor strip
- `GrapplingHookRay` — pull target
- `IceRay` — cold + slow
- `MonsterSkillRay` — monster-specific
- `PolymorphRay` — transformation
- `StoningRay` — petrification
- `TransmutationRay` — material change
- `TunnelingRay` — dig
- Plus: `FyleischCloud` — area damage over time

## Method
1. Trace full effect lifecycle: creation → application → tick → expiration → removal
2. For each ray subclass: verify side effects apply documented damage/status
3. Check `ea_Persistent` effects survive save/load (cross-ref Issue 1.1)
4. Check bounds on effect duration and magnitude

## Acceptance Criteria
- [ ] Effect lifecycle documented end-to-end
- [ ] Every ray subclass reviewed for correctness of side effects
- [ ] Persistent effects save/load verified (reuse test from Issues 3.1/3.4)
- [ ] Effect stacking/cumulative logic verified
- [ ] Bug issues filed for discovered issues
